# Write implementation tickets

Write only after the user explicitly selects implementation tickets at the end of a Grill Me interview.

Write `.scratch/plans/YYYY-MM-DD-<slug>-tickets.md`, using a concise kebab-case slug based on the settled subject.

Use only decisions and facts established in the conversation or verified from the project. Do not invent work to make the ticket list look complete.

Create the smallest coherent ordered set of tickets. For each ticket, include:

- Title
- Goal
- Expected files or owners when known
- Dependencies on earlier tickets
- Observable acceptance criteria
- Focused verification

Each ticket must be independently understandable and tied to the agreed outcome. Do not create external tracker issues.
