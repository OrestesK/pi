# Write a PRD

Write only after the user explicitly selects a PRD at the end of a Grill Me interview.

Write `.scratch/plans/YYYY-MM-DD-<slug>-prd.md`, using a concise kebab-case slug based on the settled subject.

Use only decisions and facts established in the conversation or verified from the project. Do not reopen settled decisions or invent product requirements.

Include:

- Goal
- Non-goals
- Target users and the problem being solved
- User-visible behavior and workflows
- Requirements and constraints
- Acceptance criteria
- Resolved decisions and their rationale
- Open questions, only when the user explicitly left them open

Keep the PRD product-focused. Do not include implementation steps, file names, or engineering design unless they are themselves product constraints.
